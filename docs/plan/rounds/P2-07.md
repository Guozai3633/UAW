## 3. 每项开发任务

1. 实现文档比较/报告方法和学术主张、证据、假设、冲突整理方法。
2. 采用有版本的领域方法与职责/工具上限，可复用已有RoleProfile/SkillSpec；本轮不要求先验完整技能生命周期，不按行业词典强制派发。
3. 先验单Agent粘贴文本成果；报告与论文讨论输出带定位引用、推断标记和缺口。搜索/上传/Skills按实际需要增补，不以Join/子Agent或本机执行作为本轮必需来源。
4. 核对builtin配置与当前invoke契约；未覆盖字段先修契约，不私加工具参数或自动保存用户角色。

## 6. 验收条件与必要验证

- [ ] 办公样例形成可编辑报告，用户能核对来源并提出修改。
- [ ] 学术样例区分原文主张/模型推断/未验证假设，不虚构文献或实验。
- [ ] 默认固定用户模型；单Agent办公/学术验收不需要创建子Agent、Board或Join。领域方法可关闭/替换，协作另外验收。

状态/版本/权限规则可用受控fixture验证；凡本轮声称真实模型、工具、文件、进程、联网或环境已经可用，必须保留实际回执。Mock、接口示例和HTML演示不能替代真实连通或阶段场景验收。

语义质量按原始需求、材料和证据审阅，不以字数/固定关键词替代；工具退出0也不自动证明整个用户任务完成。只加与本轮风险有关的检查，不追求测试数量。
