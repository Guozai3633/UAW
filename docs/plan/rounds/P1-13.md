## 3. 每项开发任务

1. 从原文和最小Context启动同一次固定模型调用，产生答复/工具/具体问题及必要理解摘要，Intent消费摘要不额外固定调用。
2. 拆开respond消息-only提交与正式成果流程；版本、取消、模型来源、消息持久化及账本仍由Runtime核对。
3. 按后果处理歧义：条件性解释或少量候选先回答；缺必需材料/权限才问，不能声称未执行的搜索/测试。
4. 工具回合或正式交付按真实需要升级，不使用词典分类、额外判断Agent或最高规格兜底。

## 6. 验收条件与必要验证

- [ ] 固定用户模型的真实普通无工具样本一次成功调用直接形成消息/历史，不生成Artifact/成果接受卡或强制模型自评。
- [ ] 必须材料缺失时问题可见；工具调用仍受权限/预算/效果治理，未知动作拒绝。
- [ ] 记录全部调用/重试/失败、执行与总等待、usage/pending费用；不以提示词改动冒充快通路已实现。

状态/版本/权限规则可用受控fixture验证；凡本轮声称真实模型、工具、文件、进程、联网或环境已经可用，必须保留实际回执。Mock、接口示例和HTML演示不能替代真实连通或阶段场景验收。

语义质量按原始需求、材料和证据审阅，不以字数/固定关键词替代；工具退出0也不自动证明整个用户任务完成。只加与本轮风险有关的检查，不追求测试数量。
