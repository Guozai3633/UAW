## 3. 每项开发任务

1. 按技术主选建立uv/pyproject、composition/application，冻结核心兼容版本并定义启动/关闭流程。
2. 只实现首条任务需要的ID/Ref/Failure/Principal/Scope/RequestMeta和可信上下文，从统一schema核对字段。
3. 列出七Runtime的port注入边界；用能力可用状态区分未实现与真实功能。
4. 建立原始材料、手动改动、失败日志及验收结果的fixture目录，并记录待选型ADR。

## 6. 验收条件与必要验证

- [x] 应用能启动/关闭，缺少必需配置返回可定位错误，不注册空实现工具。
- [x] 主体/批准字段不能从用户或模型参数写入可信上下文。
- [x] 形成首批开发、办公、学术任务验收表；代码目录和schema引用一致。

状态/版本/权限规则可用受控fixture验证；凡本轮声称真实模型、工具、文件、进程、联网或环境已经可用，必须保留实际回执。Mock、接口示例和HTML演示不能替代真实连通或阶段场景验收。

语义质量按原始需求、材料和证据审阅，不以字数/固定关键词替代；工具退出0也不自动证明整个用户任务完成。只加与本轮风险有关的检查，不追求测试数量。
