## 3. 每项开发任务

1. 登记模型/工具提供方、环境模板和审批政策的最小配置，支持验证后发布。
2. 实现CredentialStore port和秘密write-only输入，禁止进入模型上下文/日志/工作区。
3. 建立已认证开发主体与管理员入口；普通用户不能自报admin。
4. 发布能力旗标并在发现/调用/恢复处提供一致读取接口，未实现能力保持不可用。

## 6. 验收条件与必要验证

- [x] 管理员可配置一个模型提供方，普通Agent无法修改目录或读回秘密。
- [x] 相同配置修订可稳定读取，安全撤销使尚未执行调用拒绝。
- [x] 关闭能力后直接伪造工具调用同样拒绝，不仅隐藏按钮。

状态/版本/权限规则可用受控fixture验证；凡本轮声称真实模型、工具、文件、进程、联网或环境已经可用，必须保留实际回执。Mock、接口示例和HTML演示不能替代真实连通或阶段场景验收。

语义质量按原始需求、材料和证据审阅，不以字数/固定关键词替代；工具退出0也不自动证明整个用户任务完成。只加与本轮风险有关的检查，不追求测试数量。
