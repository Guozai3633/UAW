1. MS-I2m：A原Run控制与实际接线；B/MS-U4前端；D/MS-K1新增持久时钟组件。准确固定基线和允许目录按DISPATCH/正式分包；组件开发不等于续跑整链接受。
2. H02-I04由A独立补齐正式成果审阅暂停、接受/纠正唤醒和取消；新任务跨墙钟/进程恢复与原失败保留，准确结果见A16，不将组件或模型自评当本人接受。
3. 原子保存具体question Item、waiting状态与暂停检查点；API按主体/问题/Run版本CAS追加不可变补充，不覆盖原文。
4. 在安全边界消费纠正，按真实依赖局部失效；保留原材料与未受影响成果；受理回执与生效反馈分别展示。
5. 用户等待不耗主动执行时间；续跑复核实际剩余额度、原模型、授权/资料访问、取消和未知效果；原调用deadline不延长。
6. B接原问题回答/纠正与刷新恢复；幂等、并发答复、取消竞态、租约丢失/重启和旧客户端兼容由A/B分别验证。

- [ ] 真实页面答复后run_id不变，输入历史可追溯，无需停止/复制原问题；重复提交无新Run或重复执行。
- [ ] 等待超过主动执行预算的墙钟长度仍可按剩余额度继续；费用/审批有效期独立检查，取消和过期授权不能绕过。
- [ ] 刷新/重启不丢问题或重复计时；在途不可取消调用按原deadline/效果账本处理，纠正不撤销已经发生的动作。

状态/版本/权限规则可用受控fixture验证；凡本轮声称真实模型、工具、文件、进程、联网或环境已经可用，必须保留实际回执。Mock、接口示例和HTML演示不能替代真实连通或阶段场景验收。

语义质量按原始需求、材料和证据审阅，不以字数/固定关键词替代；工具退出0也不自动证明整个用户任务完成。只加与本轮风险有关的检查，不追求测试数量。
