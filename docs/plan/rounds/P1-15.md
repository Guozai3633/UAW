## 3. 每项开发任务

1. 建立人工查证的小样本与反例，记录原材料、正确事实、允许假设、必要澄清条件和参考依据；H01错误进入回归。
2. 固定候选/基线源码、提示词、模型配置和样本版本；区分修订集/保留集，按场景审阅而非匹配固定答案措辞。
3. 报告答案关键错误率、Reviewer漏判率及其分母、不必要阻断/缺材料错误执行，Reviewer未启用记N/A。
4. 建立相关prompt/策略改动的发布复测命令，计入全部attempt、成本/未知账单与主动/总等待；非关键阈值跑前记录。

## 6. 验收条件与必要验证

- [ ] 关键概念错误、虚构执行证据和澄清丢要求可被独立基准发现；模型passed不替代人工事实依据。
- [ ] 报告包括失败、重试和pending费用，答案错误/核验漏判/阻断可分别统计，未用Reviewer不伪造零漏判。
- [ ] 旧新实际固定模型结果可比较；当前普通交流不用固定追加模型自评；正式发布候选按已记录门槛复测。

状态/版本/权限规则可用受控fixture验证；凡本轮声称真实模型、工具、文件、进程、联网或环境已经可用，必须保留实际回执。Mock、接口示例和HTML演示不能替代真实连通或阶段场景验收。

语义质量按原始需求、材料和证据审阅，不以字数/固定关键词替代；工具退出0也不自动证明整个用户任务完成。只加与本轮风险有关的检查，不追求测试数量。
