## 3. 每项开发任务

1. 实现TaskGraph提交/PlanPatch、节点ID/依赖/环/缺输入校验。
2. 调度就绪节点，按Run账本预留并发资源、队列和deadline。
3. 节点状态独立持久化，失败/取消/失效传播到依赖后继。
4. 图仅在需要时生成；Node不等于Agent，每个节点是否委派另行决定。

- [ ] 环、缺失依赖、已过期输入和资源不足不能被调度。

- [ ] 计划修改不抹去旧费用和外部动作。

状态/版本/权限规则可用受控fixture验证；凡本轮声称真实模型、工具、文件、进程、联网或环境已经可用，必须保留实际回执。Mock、接口示例和HTML演示不能替代真实连通或阶段场景验收。

语义质量按原始需求、材料和证据审阅，不以字数/固定关键词替代；工具退出0也不自动证明整个用户任务完成。只加与本轮风险有关的检查，不追求测试数量。
