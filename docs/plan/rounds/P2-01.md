## 1. 本轮目标

把用户办公材料和论文变成可定位、可删除的资料。

## 2. 开始条件与依赖

- 前置工作包：[P1-11 第一条真实任务阶段验收](P1-11.md)。
- 整轮联调/正式验收门槛：[P1-11 第一条真实任务阶段验收](P1-11.md) 已验收。独立组件可按并行子包提前开发，不能因此跳过正式门槛。
- 在开发记录中列出实际负责人、代码基线、可用提供方/设备、场景初态和验收方式。
- 决策 `D05`：首批上传与导出格式是哪几种？ 建议文本/Markdown及论文PDF输入、Markdown报告输出；这是验收候选，不是最终格式承诺。

[查看全部待定项与最晚决策轮](../DECISIONS.md)

## 3. 每项开发任务

1. 按D05实现最小上传/格式检查/解析器，记录原资产和页/段位置。
2. 切分并建立批准profile的检索索引，构建验证后CAS发布active版本。
3. 提供状态查询、混合或基础关键词召回和引用定位，未发布数据不混入。
4. 删除原材料使索引/派生引用失效；格式失败说明缺口，不静默裁成完整材料。

## 6. 验收条件与必要验证

- [ ] 办公/论文样例内容可检索并回到实际位置。
- [ ] 过期/删除来源不再召回，来源隔离和新旧发布竞态通过。
- [ ] 上传回执只在真实字节/Hash检查后产生。

状态/版本/权限规则可用受控fixture验证；凡本轮声称真实模型、工具、文件、进程、联网或环境已经可用，必须保留实际回执。Mock、接口示例和HTML演示不能替代真实连通或阶段场景验收。

语义质量按原始需求、材料和证据审阅，不以字数/固定关键词替代；工具退出0也不自动证明整个用户任务完成。只加与本轮风险有关的检查，不追求测试数量。
