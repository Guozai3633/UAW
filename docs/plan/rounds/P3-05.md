## 3. 每项开发任务

1. 增加获准Git worktree及多隔离副本后端，记录真实基础和未提交内容。
2. 对多个writer分配独立工作区、写集合及控制租约；不把worktree当OS沙箱。
3. 三方比较base/子成果/用户当前版本，文本冲突反馈Agent或用户，二进制按文件。
4. 合并实际应用后产生新版本、ChangeSet和需重验清单。

## 6. 验收条件与必要验证

- [ ] 两个writer不直接写同一原生目录，当前用户编辑得到保留。
- [ ] 冲突不静默覆盖，未过版本检查不会合并。
- [ ] 非Git项目可使用副本路径，Git权限/基线缺失有明确受阻。

状态/版本/权限规则可用受控fixture验证；凡本轮声称真实模型、工具、文件、进程、联网或环境已经可用，必须保留实际回执。Mock、接口示例和HTML演示不能替代真实连通或阶段场景验收。

语义质量按原始需求、材料和证据审阅，不以字数/固定关键词替代；工具退出0也不自动证明整个用户任务完成。只加与本轮风险有关的检查，不追求测试数量。
