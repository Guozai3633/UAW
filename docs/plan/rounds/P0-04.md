## 3. 每项开发任务

1. 实现Conversation/InputRecord/Run受理，原文追加保存，理解输出不能覆盖原文。
2. 建立Run/InteractionItem状态白名单、事件seq及稳定item ID。
3. 实现根预算预留/结算/释放，关联operation/trace/attempt并脱敏记录。
4. 提供有序读取/断点Cursor和取消标记的基础设施，终态提交仍受完成控制器约束。

## 6. 验收条件与必要验证

- [x] 相同原文和请求ID重放得到同一个受理实体。
- [x] 非法状态跳转被拒绝，事件重复不改变已提交revision。
- [x] 失败attempt计入账本，未确定账单标pending，不能填0冒充免费。

状态/版本/权限规则可用受控fixture验证；凡本轮声称真实模型、工具、文件、进程、联网或环境已经可用，必须保留实际回执。Mock、接口示例和HTML演示不能替代真实连通或阶段场景验收。

语义质量按原始需求、材料和证据审阅，不以字数/固定关键词替代；工具退出0也不自动证明整个用户任务完成。只加与本轮风险有关的检查，不追求测试数量。
