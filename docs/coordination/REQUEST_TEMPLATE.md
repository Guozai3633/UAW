# 公共契约和基础设施变更提案

开发session在自己的 `requests/<session>/` 下新建文件；多个提案使用不同文件名。A负责处理结果，不要求开发session通过聊天工具自动给其他session发消息。

## 提案内容

- Session / 工作包 / 当前基线SHA：
- 需要修改的公共文件：
- 当前接口/对象具体缺少什么，为什么无法用已存在port完成：
- 最小改动：字段、类型、是否必填、默认/省略含义、版本与错误返回：
- 输入/输出示例（不含凭据）：
- 谁调用、谁消费、哪些旧调用受到影响：
- 权限、副作用、CAS、幂等和取消影响：
- 必要验证与回退方式：
- 是否引入新Python包/数据库迁移/事件类型：

## A：决定和发布

- 决定：采用 / 调整 / 已有接口可满足 / 暂缓及原因：
- 真实契约与实现变更提交SHA：
- 生成物与依赖锁是否同步：
- 哪些session必须同步新基线：
- 接口兼容检查与组合回归结果：

A合入并公布新基线前，开发session可继续无关任务，但不得私改公共文件或假定提案已经获准。
