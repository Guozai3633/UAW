# 范围与写入政策：开发设计

## 职责与代码位置

读取/贡献开关、范围、保留期、可信来源。

- 计划主文件：`src/uaw/context/memory/policy.py`。
- 统一业务入口：`check_memory_policy`；只允许所属 facade 或获准适配器调用。
- 上层归属：`context.memory`。该节点是逻辑组件，不默认独立服务。
- 硬约束：不因协作而默认共享私人资料。

## 输入、输出与调用协议

输入请求 `ContextMemoryPolicyRequest` 的领域字段（实验类型，实施时落在所属目录的 contracts.py）：

```text
memory_policy_ref: Ref; candidate_ref: Ref; target_scope: Scope; retention: Duration?
```

领域输出：允许写入或拒绝。结果使用 `ComponentResult[领域载荷]`；本节点只填实际确认的 `output_refs/revision`，等待、拒绝、冲突、取消和失败均为显式类型。

关联、主体与预算通过 TrustedExecutionContext 注入，不能由模型业务参数覆盖。请求/结果的公共字段与持久化边界见 COMMON_CONTRACTS；传入路径/文字不隐含访问授权。

## 详细处理策略

1. 检查读/贡献开关与用户要求。
2. 核对内容敏感范围、用途与保留。
3. 确定仅任务/会话/用户范围。
4. 拒绝或返回允许的写入范围给冲突检查。

### 模型参与方式

本组件的契约和状态处理由代码执行。涉及上游模型内容时把它作为待验证提案或数据，不再自动启动一个决策模型。

## 状态、并发与提交

政策版本记录，不把候选文字当授权。

同一逻辑请求保持request_id；重试另有attempt_id。持久修改使用预期领域版本/事务或持久执行意图；读取保持实际来源版本。Run事件只引用本节点确认的变化，不能先播成功再尝试提交。

## 失败分支与反馈

- 关闭贡献不写。
- 共享范围无权拒绝。

返回 Failure(code、retryable、failed_phase、recover_hint、evidence_refs)。代码只能恢复明确安全的执行错误；改变用户目标、模型、权限或非等价能力必须回 Agent/用户。

## 缓存、成本与取消

只处理必要候选，不强制长期存储。

使用原Run总预算和剩余deadline。取消先停止新动作，再等待执行器实际回执；已经发生的副作用不随文档/聊天回退撤销。引用读取始终复核当前授权/删除。

## 开发验收案例

- 关闭记忆仍能完成当次任务。
- 私人内容不自动共享。

这些是待实现的验收要求，本轮未运行 Runtime 行为测试。首个场景用真实输入/输出/环境建立fixture；权限、版本、取消与副作用用可重复硬检查，语义标准按人工样本校准。
