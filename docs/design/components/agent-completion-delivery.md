## 职责与代码位置

Run核对终态，Workspace发布受控成果。

- 计划主文件：`src/uaw/agent/completion/delivery.py`。
- 统一业务入口：`commit_completion`；只允许所属 facade 或获准适配器调用。
- 上层归属：`agent.completion`。该节点是逻辑组件，不默认独立服务。
- 硬约束：completed不一律等于succeeded。

## 输入、输出与调用协议

输入请求 `AgentCompletionDeliveryRequest` 的领域字段（实验类型，实施时落在所属目录的 contracts.py）：

```text
proposal_ref: Ref; expected_run_revision: int; artifact_manifest_ref: Ref; proposed_outcome: Outcome
```

领域输出：完整/部分/受阻交付。结果使用 `ComponentResult[领域载荷]`；本节点只填实际确认的 `output_refs/revision`，等待、拒绝、冲突、取消和失败均为显式类型。

关联、主体与预算通过 TrustedExecutionContext 注入，不能由模型业务参数覆盖。请求/结果的公共字段与持久化边界见 COMMON_CONTRACTS；传入路径/文字不隐含访问授权。

## 详细处理策略

1. Run核对提案来源与版本。
2. Workspace确保真实成果可访问。
3. CAS写Run终态和相应交付引用。
4. 发送完整/部分/受阻说明与验证范围，用户审阅状态另存。

### 模型参与方式

本组件的契约和状态处理由代码执行。涉及上游模型内容时把它作为待验证提案或数据，不再自动启动一个决策模型。

## 状态、并发与提交

终态与必要事件本地事务提交；外部公开发布另走Tool。

同一逻辑请求保持request_id；重试另有attempt_id。持久修改使用预期领域版本/事务或持久执行意图；读取保持实际来源版本。Run事件只引用本节点确认的变化，不能先播成功再尝试提交。

## 失败分支与反馈

- CAS冲突重读而非覆盖。
- 产物不可读不能假交付。
- 未决项保持可见。

返回 Failure(code、retryable、failed_phase、recover_hint、evidence_refs)。代码只能恢复明确安全的执行错误；改变用户目标、模型、权限或非等价能力必须回 Agent/用户。

## 缓存、成本与取消

交付引用可复用，不重生成已确认产物。

使用原Run总预算和剩余deadline。取消先停止新动作，再等待执行器实际回执；已经发生的副作用不随文档/聊天回退撤销。引用读取始终复核当前授权/删除。

## 开发验收案例

- completed/partial准确显示。
- 注册产物不会自动发邮件或发布。

这些是待实现的验收要求，本轮未运行 Runtime 行为测试。首个场景用真实输入/输出/环境建立fixture；权限、版本、取消与副作用用可重复硬检查，语义标准按人工样本校准。
