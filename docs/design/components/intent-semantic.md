# 语义解析：开发设计

节点 `intent.semantic` · UAW v0.11 · 2026-10-14 · 状态：目标策略；实际分支与回执见实施记录。

[开发设计索引](../README.md) · [公共契约](../COMMON_CONTRACTS.md) · [关系图谱](../../../ARCHITECTURE_ATLAS.md)

## 职责与代码位置

分开显式目标、推断与未知；可合并进首次模型调用。

- 计划主文件：`src/uaw/intent/semantic.py`。
- 统一业务入口：`parse`；只允许所属 facade 或获准适配器调用。
- 上层归属：`intent`。该节点是逻辑组件，不默认独立服务。
- 硬约束：不用词典判复杂度，推断不伪装用户事实。

## 输入、输出与调用协议

输入请求 `IntentSemanticRequest` 的领域字段（实验类型，实施时落在所属目录的 contracts.py）：

```text
input_refs: list[Ref]; instruction_set_ref: Ref; material_refs: list[Ref]
```

领域输出：目标/约束/候选解释。结果使用 `ComponentResult[领域载荷]`；本节点只填实际确认的 `output_refs/revision`，等待、拒绝、冲突、取消和失败均为显式类型。

关联、主体与预算通过 TrustedExecutionContext 注入，不能由模型业务参数覆盖。请求/结果的公共字段与持久化边界见 COMMON_CONTRACTS；传入路径/文字不隐含访问授权。

## 详细处理策略

1. 读取原文和有效补充，不用AI预览替代用户指令。
2. 简单任务消费首次主调用中的理解摘要，不强制先独立理解再回答。
3. 复杂指代/关键缺口需要时才深入理解，明确假设与事实来源。
4. 将必要理解绑定输入版本并CAS保存，不能为保存摘要追加固定模型调用。

### 模型参与方式

需要语义判断时，由当前继承模型提出建议；可复用当前主调用或按需发起，不强制专门判断 Agent。技术验证与状态提交仍由代码执行。

## 状态、并发与提交

解析结果提交新理解版本；原文不变，重大目标变化向用户显示。

同一逻辑请求保持request_id；重试另有attempt_id。持久修改使用预期领域版本/事务或持久执行意图；读取保持实际来源版本。Run事件只引用本节点确认的变化，不能先播成功再尝试提交。

## 失败分支与反馈

- 结构错误有界修复。
- 目标互相冲突返回ambiguity。
- 证据不足不填成确定事实。

返回 Failure(code、retryable、failed_phase、recover_hint、evidence_refs)。代码只能恢复明确安全的执行错误；改变用户目标、模型、权限或非等价能力必须回 Agent/用户。

## 缓存、成本与取消

普通无工具任务目标一次首次成功调用；重复语义分析不是强制步骤。

使用原Run总费用预算与剩余主动执行预算；合法等待用户暂停执行计时，已派发调用deadline与授权期限不变，续跑重新核对。取消先停止新动作，再等待执行器实际回执；已经发生的副作用不随文档/聊天回退撤销。引用读取始终复核当前授权/删除。

## 开发验收案例

- 解释/比较可同次回答并记录来源。
- 缺必需材料时提出具体问题而非伪造读取。
- 旧摘要不得覆盖已纠正原文。

这些是目标验收要求，本次文档生成没有运行 Runtime 行为测试；已实现范围以实际实施记录为准。首个场景用真实输入/输出/环境建立fixture；权限、版本、取消与副作用用可重复硬检查，语义标准按人工样本校准。
