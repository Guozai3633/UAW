# ADR-001：普通交流、澄清接续与成果独立验收

日期：2026-10-14。状态：**用户已接受，待开发验证**。适用架构 v0.11；不变更现行接口版本或开放功能开关。

## 1. 为什么更新

H01 人工体验暴露了三个问题：普通提问承担完整成果流程的等待；模型提问后用户无法在原任务中接续；回答有概念错误，模型自核验仍给出 passed。A32 的一次普通比较使用 3 次调用、约 108.5 秒，是具体样本，不是所有问题的性能基线。

依据：[人工反馈 H01-I02](../implementation/human-tests/H01-I02.md)、[A32 原始回执](../implementation/evidence/ms-i2l-a32.json)。旧失败、费用、取消和验收记录保留，不能用新设计改写旧结果。

## 2. 用户已经接受的八项决策

| 编号 | 决策 | 影响和原因 |
| --- | --- | --- |
| Q1 | 普通解释、比较、发散以一次首次调用直接回答为目标；理解和语义评审按需 | 减少固定前后模型调用；真正需要工具、重试或补充时仍可以多次调用 |
| Q2 | 澄清答复接续同一个未结束 Run | 用户无需停止、重新拼写原问题；保留上下文与未受影响成果 |
| Q3 | 增加人工核对样本和反例的正确性门槛 | 区分答案错误、核验漏判、不必要阻断，不以模型自评代替事实判断 |
| Q4 | 单 Agent 办公、学术成果独立于子 Agent、共享板和 Join 验收 | 普通成果不应等待协作设施；协作另行验收 |
| Q5 | 普通回复默认只保存消息与历史 | Artifact、DeliveryProposal、成果接受仅用于相应正式交付契约，不给每句话增加审阅步骤 |
| Q6 | 等待用户时暂停执行计时；费用与授权期限分别约束 | 晚些回答仍可继续；审批、调用、目录授权不因暂停自动延长 |
| Q7 | 正确性评测主要用于版本发布 | 相关提示词或策略改变须复测；普通回复不固定增加一次模型自评 |
| Q8 | 下次真人体验聚焦对话、澄清、纠正、单 Agent 粘贴文本成果 | 本机文件链独立推进和验收；先把已具备材料入口的完整体验做好 |

这是用户在方案审查中两轮全部同意后的记录，不再将这些方向列为待用户选择。

## 3. 开发范围与未完成项

v0.11 是目标架构。A32 已有自然交流提示词、等待问题展示、文本成果与部分控制基础，但 `respond` 仍走成果登记和核验；快通路、用户可用的同 Run 澄清及暂停计时尚未完成。模型自己评为 passed 不能证明事实正确。

七个 Runtime、固定用户模型、动态工具、子 Agent/DAG、代码与本机能力继续保留。此次调整改变默认执行和验收顺序，不缩减完整目标。不得据此恢复取消的旧任务、重发 unknown 调用或扩大真实权限。
