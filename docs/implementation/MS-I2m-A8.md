## 原因与修复

A7 `ExecutionSegments.deadline()` 仅当原deadline已经过期才检查实际执行段。真实用户较早回答时，新的ctx.deadline已按剩余主动额度后移，原墙钟仍有效；模型预留使用新ctx，预算检查却钳在旧ledger.deadline，产生不一致。

修复仅改变 A 所有的执行段选择条件：当 caller deadline 超出原 Run/ledger 上界且当前调用未过期时，立即验证实际已签发的段；仍需精确ctx、原作业/时钟历史、当前binding/clock、原预算摘要和完整主体。普通原上下文保持无段查询路径；缺段沿用原上界，篡改新期限被拒绝，旧预算/调用/审批/native期限与资源总额不改。

新增实际时钟SQL覆盖“原期限尚有效时回答”和“原期限尚有效时纠正”，两项修复前都复现同一个budget_deadline_invalid。修复后定向回归包含早答复、长等待、伪造期限、取消、回滚和文本交付；最终结果及固定源码在准确发布回执中给出，未执行的命令不算通过。
