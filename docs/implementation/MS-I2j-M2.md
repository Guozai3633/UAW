# MS-I2j M2：实际后台任务与成果读取

日期：2026-10-10。阶段交付，不是 MS-I2j 全量或真实页面验收。

## 实际实现

- 网页/CLI 原文受理和后台 job 同一事务写入；容量不足回滚整次受理。同一个 request_id 返回原 Run，不再入队。队列最多 64、并发最多 4，默认 16/1。
- 持久阶段依次消费已有理解、固定用户模型、实际单 Agent 和完成组件。重启保留原操作/attempt；未知效果先停留原尝试，不自动重发。工作租约 300 秒，每 15 秒续租，fence 拒绝失效 worker 提交。
- 内部权限在运行中复查当前 Web 会话；退出/失效不能保留旧身份执行新动作。取消后独立终态控制器检查活动资源、Model/Tool 效果与账务；未确认效果不伪造 cancelled。
- 返回实际文本/Markdown、原始 Artifact、逐要求 VerificationReport、Contract、DeliveryProposal 和固定 Bundle refs。只有完成控制器能置 completed；合同需要用户接受时等待真实相同会话主体决定。
- 成果可按当前用户拥有关系读取；历史读取不授予新执行权限。内容必须匹配准确版本、UTF-8 字节和 SHA256。接受拒绝旧目标/版本/取消；决定与取消使用同一会话事务锁。
- 当前三种办公本地工具必须来自管理员已登记提供方。后台开关默认关闭；显式配置实际依赖缺失时启动失败，不创建虚假提供方。

## 当前验证

23 个不同真实 PostgreSQL/HTTP 节点最终通过：10 个控制/队列/查询、11 个完成/成果、2 个实际完整后台链。两条链的 Model HTTP 为受控回复，验证实际模块装配及协议，不证明 LLM 质量。

保留原准备失败、可选字段契约失败、verification 引用类型错误及 HTTP 测试装配遗漏。具体节点采用最后回执去重，不把重复复跑累加。

严格静态和类型检查通过。固定来源、原始 XML、历史失败、校验摘要以 [阶段证据](evidence/ms-i2j-m2.json) 为准。
