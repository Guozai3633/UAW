## 2. 841项通过意味着什么

上一集成版本841个唯一测试节点全部通过，包括真实PostgreSQL、临时本机路径和真实Ed25519；静态/格式156文件、Mypy102源码文件通过。它证明已实现边界兼容，没有证明真实LLM、用户配对、执行工具或页面已经可用。

两批实际检查累计1443.84秒（约24分钟），覆盖674个组件用例＋167个其余用例。A此前还承担接线、缺SQL补跑、测试修正和发布整理；worker包较小，因此出现20分钟交付后长时间等待。瓶颈是任务拆分和验证职责集中，不能靠继续增加小包改善。

## 3. 本轮调整

- B/MS-C5：通用上下文的登记→当前来源→快照→模型输入完整链。
- C/MS-T2d：只读工具invoke→真实text adapter→持久结果→恢复读取完整链。
- D/MS-R2d：实际OS控制密钥签名＋授权根来源＋装配验证。
- A/MS-I2g：独立数据库、跨模块契约和接线、可信来源与整体验收。

每包四个连续里程碑，两个交付点；先报告阶段版接口，继续完成本包，不按一个小函数或一批测试拆包。包大小由完整能力/目录边界决定，不承诺固定耗时或四个session始终100%忙碌。

SQL下放到worker自己的数据库；A/B/C/D分别使用独立Docker project、端口和数据卷。worker完成模块验证，A以受影响模块和组合链路验证为主，全量在集成里程碑跑一次。依赖造成的等待仍会存在，A应在阶段版接口到达时先接线并及时处理公共提案。

## 4. 距离首条真实任务的关键路径

通用Context与只读Tool实际链 → 真实提供方和当前权限接线 → 单Agent有限步循环/取消/审批 → 成果与证据核验 → 聊天页面 → 第一条真实任务验收。开发人员的本机代码任务还需可信IPC、项目授权、执行模式D03、真实进程/test和变更审阅。

本轮优先让可用链路前进；缓存、签名和恢复只在支持该链路所需范围继续建设。推特包装仍后置。

详细任务、接口、修改目录和验证方法见 [MS-I2g发包定义](../coordination/requests/A/MS-I2g-parallel-packages.md)，可转发说明见 [NEXT_WAVE](../coordination/NEXT_WAVE.md)。
