# P0-02实施记录：开发持久化适配器

日期：2026-10-07。状态：开发适配器与必要场景已验证；D01最终权威部署未确认，计划状态保持开发中，不将本机开发数据库当作产品部署结论。

## 实现范围

- 实际PostgreSQL 17.11开发实例，镜像digest固定在ops/compose.yaml；SQLAlchemy/Psycopg/Alembic实际组合锁定。
- 当前控制面记录按主体/namespace/ID分区；每写操作独立事务/Session。
- CAS创建/更新、同request参数Hash冲突、不可变历史修订、逻辑删除和删除后幂等结果访问复核。
- 数据、去重记录、不可变修订和Outbox一起提交；SQL消费者回执与投影修改同事务，失败可安全重新消费。
- FSBlobStore使用私有目录、主体分区和Hash定位，真实内容大小/完整性核验，重复并发写保持同一内容。
- 两次实际迁移；应用检查数据库版本，拒绝未迁移就绪。

## 真实证据

[统一测试回执](evidence/p0-tests.xml)包含：

1. 独立Python进程读取已提交InputRecord，中文原文不变。
2. 重复提交只产生一条记录；同ID不同参数返回冲突。
3. 两个并发CAS只有一个成功。
4. 主体隔离、返回数据脱离ORM，内存修改不污染持久状态。
5. Outbox冲突回滚整条记录及去重占位；修复后可重试。
6. 重复消费者只提交一次投影；消费者失败回滚后可再次消费。
7. 固定旧修订可读；逻辑删除后旧修订、旧幂等请求均不能返回内容，不能以创建复活。
8. Blob新适配器重读、主体隔离、路径参数拒绝、摘要篡改、并发写和大小限制。

实际发现并修复：Windows默认Proactor循环不兼容Psycopg，改为显式control_plane_loop工厂；Windows并发mkdir期间解析未存在路径不稳定，改为检查既有祖先、建立父目录后重新核对。Runner未来在独立进程运行，不沿用此数据库循环处理子进程。

## 边界与未完成

- RecordStore是内部设施，具体业务状态/不可变输入规则仍由各Runtime仓储负责；没有公开任意数据库写接口。
- 消费者去重只保证同事务SQL投影，不保证任意外部副作用恰好一次。
- Blob目录必须由控制面OS账号独占管理；它不替代后续Runner对用户项目的Handle/链接/沙箱安全实现。
- 当前逻辑删除约束记录读取；完整资料删除、事件/索引/缓存保留与跨域清除由后续所属领域实现，不能宣称本轮已有全局遗忘能力。
- 未完成P5检查点恢复、全量备份恢复演练、生产部署或模型调用。
- D01仍需产品选择。没有创建双主历史、云服务、额外向量数据库或用户任务执行环境。
