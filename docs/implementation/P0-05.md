## 实际执行链路

`ModelCall + TrustedExecutionContext` → 核对Run/会话/原始模型选择 → 校验固定目录与当前执行政策/提供方撤销 → 读取归属正确的输入快照 → 校验协议、参数、窗口与schema → 读取私有凭据 → 持久调用意图 → 每attempt预留 → 发送前复核 → 提交dispatch意图 → HTTP请求 → 保存完整响应及文本 → 记录观察用量并结算 → 保存ModelOutput与调用回执。

输入来自实际保存的原文；模型无法提交另一个模型、提供方、权限主体或响应模型名称。当前根政策同时用于子调用的默认继承基础；会话子Agent定义、显式子模型授权和实例创建仍在P2，不能由本轮继承fixture宣称已经实现。

## 策略与边界

1. 新增显式profile `provider_profile:model.chat_completions@1`。旧 `model.http@1`仍是登记profile，不会自动推断其协议。HTTPX承载此协议；实际供应商SDK仍依D06选择，并可在同一provider port后替换。
2. endpoint、model_name、输出参数名、temperature/推理档位和响应别名均由管理员声明。响应模型与登记名称不同且未被批准为别名时失败；不会静默接受另一模型。地址、凭据仍由P0-03保护。
3. 本轮为有界非流式请求。最多2次尝试，只对连接建立失败和明确429拒绝重试；读取超时、其他HTTP错误、解析/结构失败与取消不自动重发。所有尝试固定同一目录模型，每次都有独立attempt与额度。
4. 同逻辑调用只有一个持久claim拥有发送资格。并发重读返回已有结果或明确pending；同ID改参数冲突。进程在claimed/dispatch之后退出时不会自动再发，完整核对与安全续跑属于后续恢复阶段。
5. 当前能力政策固定修订、会话范围、model.generate及endpoint域名均需匹配。改修订会使旧上下文失效。发送前再次核对，运行中轮询取消/政策变化/提供方撤销并关闭请求；关闭请求不等于撤回供应商已收到的输入，也不证明未计费。
6. 文本与成功HTTP响应完整存入私有Blob；短文本字段最多16384字符，截断预览时text_complete=false并返回完整Ref。length/refusal只是供应商结束原因，不代表用户任务完成。
7. 工具名映射到可信快照中的固定ToolSpec，再按schema检查参数并产生稳定逻辑动作ID。未知工具拒绝；这里不执行工具。本轮诊断快照没有可用工具，Tool Runtime尚未接入。
8. 结构输出还要通过本地schema校验；拒绝所有schema引用、动态正则及超出大小/深度的定义。外部材料只进入数据消息，不升级为系统指令；完整指令继承与上下文装配仍在P1。
9. 供应商Token及cached_tokens来自回执。缺失字段省略；解析失败保留可确认的Token观察。标准协议未给费用，因此Usage为pending、money省略并保留管理员声明的reservation_money；该值是额度估计，不是价格或账单。实际价格核算/费用核对后续接入，不能填0冒充已确认。
10. 日志只记录固定操作名和错误类型；认证头不进入数据库、prompt或调用回执。私有实连摘要不自动提交到公开文档。

协议请求、工具/结构输出和usage字段核对自[官方Chat Completions API](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create)。其他提供方即使声称兼容，也必须单独实连验证，不能据此假定所有模型支持相同字段。

## 本轮实际验证与未过项

- 实际PostgreSQL：并发去重、改参数冲突、固定模型/配置、能力变化、来源与Run归属、两次尝试分别记账、超时后重读不重发、未知费用保留及取消。
- 实际Windows凭据库：测试凭据私有写入、发送到受控协议fixture、清理；不把测试秘密作为用户API密钥。
- 实际loopback HTTP：请求字段、Authorization及禁用环境代理；这是协议fixture，不是LLM。
- 受控响应：长输出Ref、结构成功/失败、未知工具、响应上限、不跟随重定向、缓存Token、格式失败和保留已观察用量。
- **尚无真实LLM输出/usage/账户可访问性回执，P0-05不标accepted。** 自动任务领取、Agent循环、流式Item/SSE、完整Context、工具执行、价格核对和组合checkpoint均未完成。
