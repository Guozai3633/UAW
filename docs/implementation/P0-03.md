# P0-03：管理员配置、凭据与功能开关

日期：2026-10-07。范围：单用户、本机开发控制层。执行：Codex。代码与环境摘要见[环境回执](evidence/environment.json)，测试原始结果见[JUnit](evidence/p0-tests.xml)。

## 本轮实现

- [配置入口](../../src/uaw/shared/configuration.py)：模型提供方、模型目录、政策及最小环境模板登记；草案 → 校验 → 激活。每个修订保存不可变版本，发布时写入持久事件。
- [开发认证](../../src/uaw/api/authentication.py)：独立用户/管理员令牌，角色由部署配置决定。请求中的 principal、admin、approved 等字段不能授予权限。仅监听本机地址；带浏览器 Origin 的请求暂时拒绝。
- [凭据接口](../../src/uaw/shared/credentials.py)与[Windows 实现](../../src/uaw/infrastructure/credentials.py)：只选择 Windows Credential Manager，不能回退到明文文件或第三方不安全 backend。管理接口只写入并返回句柄；没有秘密读取路由或 Agent 工具。
- [管理员客户端](../../ops/admin_cli.py)：从受保护配置读取令牌；第三方凭据通过隐藏终端输入提交，不放在命令参数或 payload 文件中。
- 发现、调用、恢复、子 Agent 共用配置开关检查入口。当前代码执行、本地文件、多 Agent、搜索、MCP、记忆和扩展包全部关闭；不能通过把 enabled 改成 true 启用尚未实现的能力。

## 具体策略与边界

1. 提供方 profile 使用 `provider_profile:model.http@1`；设置仅允许 model_name、timeout_ms。地址只接受 HTTPS 或开发机 loopback HTTP，拒绝 URL 中的账号、密码、查询参数和片段。
2. 提供方登记结果是 disconnected。模型目录 active 表示管理员登记启用，**不表示已联网或模型调用成功**。SDK/协议适配与实际连通属于 P0-05。
3. 配置引用必须存在且版本匹配。当前只支持 manual 审批政策、无副本缓存的开发存储、无安装/执行动作的环境模板；环境模板使用修订编号作为版本。审批请求、签名、安装和进程启动尚未实现。
4. 开发数据库只支持 local_authoritative 部署声明；这不决定最终产品的 D01。本轮没有云端部署、OIDC 登录或历史加密能力，相关配置不能伪装成可用。
5. 固定配置按 id + revision 读取；提供方撤销检查读取当前状态。旧快照不能恢复已撤销提供方。当前撤销是终止状态，重新接入需后续明确的恢复机制。
6. 凭据句柄由平台、提供方与 request_id 确定。平台事务锁内核对旧秘密，再写入 OS 凭据库；同请求不同秘密冲突。数据库只保存句柄归属与回执，去重哈希不包含明文秘密。
7. OS 写入与数据库提交不是分布式事务。数据库提交失败可能留下受保护的孤立句柄；相同请求可核对并重试，批量孤立句柄回收后置。不能把它描述为跨系统原子提交。
8. Windows 凭据库是开发主机信任边界。生产 Secret Manager 与运行不受信代码的隔离账户/环境仍须后续接入；本轮没有开放本地代码执行。

## 真实检查

- 实际 Windows 凭据写入、独立适配器重读及清理成功；并发同请求不同值只有一方成功，另一方冲突，秘密不会被替换。
- 普通用户写平台配置/凭据被拒绝；HTTP 请求自报角色被 schema 拒绝；未经认证不能读取目录。
- 草案未校验不能发布；引用冲突完整回滚；固定版本可重读；撤销后旧快照的模型准入拒绝。
- 四个能力检查边界均拒绝已关闭功能；真实 Tool Runtime 的完整执行闸门在 P1-03 接入。
- 注册使用受控 `.invalid` 提供方 fixture，没有发起供应商网络请求。数据库为实际 PostgreSQL，秘密存储为实际 Windows backend；fixture 不代表模型连通。
