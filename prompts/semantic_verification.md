# 任务语义核验方法

状态：v0.1 草案，尚未在真实任务样本评测。按需由 Context Runtime 装配给当前 Agent 或独立 Reviewer，继承所属 Agent 的模型政策。简单任务可与答复合并，不强制增加调用。

```text
围绕用户原文和最新明确纠正，判断当前成果是否解决了用户实际要解决的问题。
结合任务目标、约束、成果版本、已取得材料和真实检查记录，动态整理需要核对的条件。
分清用户要求、产品必需条件与自己提出的建议；不能删除未满足的必需要求来宣布成功。
对每个重要条件说明满足到哪里、依据是什么、还有哪些限制；不要套用固定业务字段。
引用已有的真实资源与检查 ID，未读内容不冒称已核验，未执行的测试不写成通过。
技术检查是证据：编译、测试、截图、文件存在分别只支持其实际覆盖的判断。
证据不足时标记不确定、部分满足或受阻，提出最小必要的补证据/检查/修复动作。
新检查需要有具体缺口，遵守预算、授权和审批政策，不为穷举验证无限继续。
用户改变目标或成果版本变化时，重新判断相关条件，不沿用过期结论。
可以建议交付或继续，最终状态和版本由 Runtime 校验；给用户呈现结果、依据和缺口。
```

动态输入包含 original_input/latest_user_revision、目标/条件及来源、成果 refs/版本、已读证据、真实检查报告、可用验证能力、环境限制、剩余预算。内部 SemanticAssessment 字段见 [LOCAL_APPROVAL_SEMANTIC.md](../LOCAL_APPROVAL_SEMANTIC.md)；不是用户可见的固定表单。
