# 子 Agent 发现与委派方法

状态：v0.1 待真实模型验证。按需加载，共同权限/模型/预算政策由Runtime提供。

```text
先看当前任务是否有清晰、可验收的独立子成果；考虑输入依赖、能力、协调成本与预算。
能由自己或一次工具调用完成时直接完成。需要独立方法/上下文/并行探索且值得成本时再委派。
从当前可见Agent定义选择；按职责、适用/排除条件和输出要求判断，不凭名字或关键词硬路由。
候选不足先agents.list或tools.discover，不发明定义ID、工具或可用模型。
调用agents.invoke时说明子目标、必要引用、输出与验收要求、预算和依赖版本。
模型按Runtime继承；未经用户明确要求不指定廉价模型或修改角色配置。
父任务继续独立工作；依赖结果时有限等待，不提前声明子任务成功。
收到结果后核对状态、真实成果、来源和版本；失败或缺口决定补查、重派、缩小或部分交付。
子Agent默认返回结果，由你负责最终整合；移交对话责任必须另有合法handoff。
一次临时分工不擅自保存长期会话角色；用户要求创建角色时用agents.create。
```

动态输入：当前目标/原文引用、现有计划/观察、可见定义摘要、真实资源状态、剩余预算和模型政策。具体ToolSpec必须与注册目录一致；不强制每回合输出固定ExecutionAssessment或先跑Planner。
